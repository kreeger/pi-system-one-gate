# MCP gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, no subagent tool is available in this session) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the `system-one` link judge `mcp` permission asks with System One, auto-approving only `safe` at P(safe) >= 0.90, and deferring everything else.

**Architecture:** A pure MCP pre-check (no-preview defer, write-verb defer) runs first. It then hands a `{ target, input, cwd }` state to the same cap-ask-threshold core that bash uses, with its own instructions. `index.ts` routes by `payload.kind`.

**Tech Stack:** TypeScript (ESM, `.ts` import paths), `node:test` via `tsx`, `tsc --noEmit`, `system-one-core` 0.2.1, `@gotgenes/pi-permission-system` 41.0.0.

**Spec:** `docs/superpowers/specs/2026-10-20-mcp-gate-design.md`

## Global Constraints

- `allow` only when `choice === "safe"` and `probabilities.safe >= 0.9` (`THRESHOLD`, inclusive). Unchanged.
- The gate never returns `deny`.
- Serialized state cap: 8192 UTF-8 bytes. Over cap defers `over-cap`, no call, never truncate.
- Redact every string that goes into state with `redactForReview`.
- The decision log entry never contains the target, input, cwd, or serialized state. Only `reviewFields` output.
- Bash behavior is unchanged. Existing tests must still pass unmodified (except where a step says otherwise).
- Keep `npm test` and `npm run typecheck` green after every task.

## Review Focus

- MCP ask with no `input` evidence (tool has no formatter, or the formatter returned nothing) → defer `no-input-preview`, no call. A bare target name is never judged.
- Write verb in camelCase or mixed case (`deleteIssue`, `Create_Item`) → defer `write-verb`. Token matching must split camelCase.
- Write verb inside a longer word (`settings`, `sender`, `created_at` as a noun) → must not defer just on substring. Token match only (`set` does not match `settings`).
- Secret-looking text inside the MCP input preview (`token=...`, `Bearer ...`) → redacted before the state is built and before the cap check.
- MCP input near the cap (8192 bytes) → exact boundary behavior matches bash: 8192 judged, 8193 over-cap.

## File Structure

- Create: `src/mcp-gate.ts`. Responsibility: MCP pre-checks (`writeVerbOf`, `mcpInputOf`) and `judgeMcpCall`. Pure over injected `ask`.
- Modify: `src/gate.ts`. Responsibility: export a shared `judgeState` (cap, ask, threshold map). `judgeCommand` becomes a thin wrapper around it. Widen `GateState` and `AskFn` to accept `McpState`.
- Modify: `src/backend.ts`. Responsibility: `createAsk` takes an optional `instructions` (default: the existing bash text). Export `MCP_INSTRUCTIONS`.
- Modify: `src/index.ts`. Responsibility: route by `payload.kind`. Build an MCP ask with `MCP_INSTRUCTIONS`.
- Create: `tests/mcp-gate.test.ts`. Responsibility: pre-check and `judgeMcpCall` unit tests.
- Modify: `tests/index.test.ts`. Responsibility: routing tests for `mcp` kind.
- Create: `eval/mcp-cases.jsonl`. Responsibility: hand-labeled MCP cases, `{ id, label, target, input }`.
- Modify: `eval/run.ts`. Responsibility: `--mcp` flag runs the MCP cases through `judgeMcpCall`.
- Modify: `README.md`. Responsibility: MCP section and eval numbers after the live run.
